premise_sim.png — the shipped premise figure. Synthetic, generated by
  src/lib/core/premise-sim.js (the model) via
  scripts/dataset-summary/emit_premise_sim.mjs + premise_figure.py (the render).
  Models the phenomenon rather than reproducing a recording: AP-linked calcium
  summing linearly from clusters of 1-5 action potentials, plus three calcium
  events with no spikes beneath them, in TWO morphologies (2026-07-31) both seen
  in the real data — a tall, brief, symmetric bump (gaussian, sigma 0.9 s) and a
  medium-rise/very-slow-decay event (2.7 s to peak, 12 s decay constant). Neither
  matches the AP-linked transient, which is the point: an event that does not fit
  the AP kernel is one a kernel fit cannot explain. Three figure panels — the full
  trace, then one zoom per morphology. Parameters are matched to the ROI-1
  reconnaissance (kernel peak +0.6 s, tau ~2.7 s, noise sigma ~0.0035 dF/F0) so
  the figure is quantitatively plausible, but no real sample is reproduced and
  nothing in it is evidence about the real cell. Guarded by 10 tests in
  core.test.mjs.

  Regenerate:
    node scripts/dataset-summary/emit_premise_sim.mjs darkroom/premise_sim.json
    darkroom/venv/bin/python scripts/dataset-summary/premise_figure.py \
        -o docs/img/premise_sim.png
    cp docs/img/premise_sim.png src/lib/assets/premise_sim.png

  Because it is synthetic it carries NO disclosure cost, which is the whole
  reason it exists — it can be zoomed, shipped as per-sample data, or made
  interactive with no consent question at all. That was impossible with the
  real figure and is the reason for the switch.

REDRAWN 2026-07-30 — TWO PANELS, TICKS BELOW THE TRACE. The figure is now:
top, the full recording with the 400-700 s window shaded; bottom, that window
enlarged on the SAME dF/F0 scale, where 54 action potentials are followed by
almost no calcium. Spike ticks moved from above the trace to below it, so the eye
drops from a tick up into the transient it caused.

The shared y-scale is deliberate. Letting the lower panel autoscale would redraw a
collapsed response as healthy signal, and amplitude is the figure's whole argument
(same principle as ADR-0024/0029: display scaling must not mislead about
magnitude).

methods_explainer.{pdf,png} is a plain-language, graphics-first teaching figure —
"Three ways to recover a calcium kernel — and one check on them" (free-vector /
parametric / shaped, plus STA). Its curves are SYNTHETIC/illustrative (no
unpublished data), so unlike roi1_trace.png it is data-safe and needs no consent
gate. Generated by scripts/dataset-summary/methods_explainer.py (edit + re-render
there). Colors and method names match the dataset-summary pages.

RETITLED 2026-08-23 — THREE METHODS, NOT FOUR. It read "Four ways to ask if there
is a calcium kernel" and footed "all four roughly AGREE", which contradicted canon
(methods.html §6 is "Three parallel recovery methods"; §7 files spike-triggered
averaging separately as the validation partner, which assumes no kernel and solves
no inverse problem) and contradicted the Tab 0 prose directly above it. Calling STA
a fourth method quietly converts an independence check into a fourth estimate.

Also changed in the same pass, all found by murderboard:
  - x-axis "time after spike (s)" -> "lag from spike (s)". The old label was
    self-contradictory over a -5..+5 s range, and the negative half is load-bearing
    (ADR-0009 keeps it deliberately; the shaped method penalises it explicitly).
  - the STA panel's plot title "recovered kernel" -> "spike-triggered average",
    since it is not a recovery.
  - its caveat "blurs when spikes crowd" -> "discards spikes with close
    neighbours". The shipped STA REJECTS crowded spikes rather than averaging them
    together, so a crowded recording starves rather than blurs: measured at the
    shipped 1 s window, 31/33 spikes accepted at 0.1 Hz but only 10 of 1515 at 5 Hz.
  - a footer line saying the panels are ILLUSTRATIVE. They are drawn from a single
    k_true array (free-vector = k_true + noise - tilt, STA = a box blur), so the
    figure's own bottom line -- "if a real kernel exists they roughly AGREE" -- was
    a check that could not fail. Making it evidence means computing the panels from
    recoverKernel / recoverKernelParametric / recoverKernelShaped /
    spikeTriggeredAverage; that is still open.
